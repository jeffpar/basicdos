#
# BASIC-DOS Distribution Manifest
#
# Each [section] lists the files (relative to the repository root, with optional
# wildcards) that belong in the corresponding folder of a BASIC-DOS disk:
#
#   ROOT     the root directory, in order; "CONFIG.SYS" stands for each disk's own
#            CONFIG.SYS (followed by AUTOEXEC.BAT, if its SHELL lines run one)
#   EXT/CMD  the external BASIC-DOS commands that are assembly language
#            programs (including DEBUG.COM, which is also an installable
#            device driver), and HELP.TXT, which HELP displays (distribution)
#   EXT/BAS  the external BASIC-DOS commands that are BASIC programs (eg,
#            FORMAT.BAS and LS.BAS) (distribution)
#   EXT/DLL  the NE libraries (DLL files), which the kernel's NE loader looks
#            for there, unless a LIBPATH= line in CONFIG.SYS names another
#            directory (distribution)
#   DEMOS    demo programs (distribution), including DONKEY.BAS, the only PC
#            DOS 1.00 BASIC sample on every disk
#   TESTS    BENCH.BAS, STRESS.BAT, and REGRESS.BAT (which runs the tests in
#            TESTS/REGRESS)
#   TESTS/REGRESS  the regression tests: each checks its own results (printing
#            "passed" or "failed", and setting an exit code if it's a program),
#            runs unattended in one session on any machine and in either mode
#            (skipping what it can't test there), and is run by REGRESS.BAT and
#            tools/tests/quick.sh
#   TESTS/MISC  every other test program: those that need something more (eg,
#            GFXTESTS.BAS needs a CGA, V86TESTS needs V86.COM, DBGTESTS needs a
#            debugger, and MEMTESTS needs a protected-mode machine with several
#            sessions), cause a fault or failure on purpose (FAULT, ASSERT),
#            measure rather than check (MICRO.BAS), or just run (PIPES.BAT,
#            RANDOM.BAT, and the BAT and EXE versions of PRIMES)
#   TESTS/SAMPLES  the rest of the PC DOS 1.00 BASIC samples (hard disk only)
#            (ie, demos/samples/*.BAS except for any file that DEMOS lists)
#   TOOLS    tools used for testing (DISKREAD, DISKWRIT, SYMDEB, and MSBASIC)
#
# The software/src/tests folders match: the TESTS files are in tests, and the
# sources of the TESTS/REGRESS, TESTS/MISC, and TOOLS files are in tests/regress,
# tests/misc, and tests/tools, with the programs built in their OBJ folders.
#
# A section named FOLDER/SUBFOLDER (eg, DEMOS/WOLF3D) is a subfolder of FOLDER,
# and a file inside a disk image can be listed as the image's path (which PCJS's
# diskimage.js resolves) followed by the file's path within the image.
#
# gulpfile.js builds the BASICDOS-360K distribution diskette and every demo
# diskette with ROOT, EXT (CMD, BAS, and DLL), and DEMOS (and a demo diskette also has, in TESTS,
# the test files that its CONFIG.SYS runs, eg, PIPES.BAT, and any that
# gulpfile.js lists for it, eg, FPUTESTS.COM on the Single diskette, whose
# machines have a coprocessor), the BASICDOS-360K-TESTS diskette with
# TESTS (and its REGRESS and MISC subfolders) and TOOLS, and the BASICDOS-10MB
# hard disk with all of them (plus TESTS/SAMPLES, DEMOS/WOLF3D, the WOLF3D.BAT and JIVE files that only it has
# in DEMOS, SRC, and the build tools in TOOLS/BIN, with the C compiler's include
# files and libraries in TOOLS/INCLUDE and TOOLS/LIB, and the C startup,
# floating-point, STUB, and BDC sources in TOOLS/CRT, FP, STUB, and BDC, and
# C demos in TOOLS/DEMOS).  tools/tests/prep.sh copies the EXT folders
# into each test configuration's EXT folder, DEMOS and TESTS into its TESTS
# folder, TESTS/REGRESS and TESTS/MISC into its TESTS\REGRESS and TESTS\MISC
# folders, and TOOLS into TOOLS.
#
